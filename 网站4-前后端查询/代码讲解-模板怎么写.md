> 对应模板：`C:\Users\Administrator\Desktop\通用模板(1)\index.py`、`前端模板.html`

## 0. 先把模板拆开看：它其实只给了 5 样东西

模板 `index.py` 只有 42 行，但已经把 Web.py 项目的“骨架”写全了：

| 模板里的东西 | 作用 | 对应本项目 |
| --- | --- | --- |
| `import web` / `import pymysql` | 用 Web.py 做网站、用 PyMySQL 连 MySQL | 保留，见 `app.py` 开头 |
| `def sqlSelect(sql)` / `def sqlWrite(sql)` | 连接数据库、执行 SQL 的两个函数 | 升级成 `get_connection()` / `fetch_all()` / `fetch_one()` |
| `urls = (...)` | URL 路由表：哪个网址交给哪个类处理 | 扩成 5 个页面路由，见 `app.py:295` |
| `class index: GET(self) / POST(self)` | 一个页面的处理类；GET/POST 对应两种请求方式 | 扩成 `IndexPage`/`CalendarPage`/`OrganicPage`/`ResumePage`/`BootstrapPage` |
| `render = web.template.render('templates/')` | 告诉 Web.py：HTML 模板放在 `templates/` 目录 | 保留，`app.py:46` |
| `app = web.application(urls, globals())` | 把路由表变成真正可运行的网站 | 保留，`app.py:304` |
| `session = web.session.Session(...)` | 登录会话（模板自带，实验用不到） | 本项目没有登录功能，直接不用 |
| `app.run()` | 启动网站，默认 8080 端口 | 保留；另外加了没有 cheroot 时的“兜底启动” |

`前端模板.html` 是 Bootstrap 3.3.7 + jQuery 的页面骨架，模板用 CDN 引入，本项目改成了本地 `static/` 文件（不上网也能显示）。

**一句话总结模板：**
> 模板 = 路由表 + 处理类（GET/POST） + 模板目录 + 两个数据库函数 + 启动入口。
> 写代码 = 在这个骨架上“填页面、填处理逻辑、填 SQL、填模板”，不需要从零搭框架。

## 2. 按顺序写代码：6 步

### 第 1 步：先准备数据库（模板里没有这一步）

模板默认数据库和表已经存在。我们的数据在 CSV 里，所以要先把数据放进 MySQL：

```sql
-- sql/setup.sql，用 root 执行一次
CREATE DATABASE IF NOT EXISTS web DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'web'@'localhost' IDENTIFIED WITH mysql_native_password BY '你的数据库密码';
GRANT ALL PRIVILEGES ON web.* TO 'web'@'localhost';
```

```bat
mysql -uroot -p < sql\setup.sql
python init_db.py
```

`init_db.py` 做的事：
1. 读 `data/organic.csv`（`utf-8-sig` 去掉 BOM）；
2. `CREATE TABLE organic(...)`：CSV 有 12 列就建 12 个字段，`id` 主键，`name`、`cas` 建索引；
3. `executemany()` 一次插入 271 行，最后 `COUNT(*)` 确认条数。

**先做这一步的原因**：后端写查询时，数据库里已经有真实数据，才能边写边验证“甲醛是不是 4 条”。

### 第 2 步：写 config.py，把模板里写死的连接参数抽出来

模板的写法：

```python
conn = pymysql.connect(host='localhost', port=3306, user='root', passwd='123456', db='web')
```

问题：写在两个函数里，改密码要改多处；也不适合把密码散落在业务代码里。
所以新建 `config.py`：

```python
DB_CONFIG = {
    "host": "127.0.0.1",
    "port": 3306,
    "user": "web",
    "password": "你的数据库密码",
    "database": "web",
    "charset": "utf8mb4",
    "connect_timeout": 5,
}
ORGANIC_TABLE = "organic"
MAX_RESULT_ROWS = 30
```

以后所有地方统一用 `**DB_CONFIG`，改一处就够。

> 为什么不用模板里的 root/123456？
> 本机 MySQL 8.0 的 root 密码不是 123456；而且 MySQL 8 默认的 `caching_sha2_password`
> 认证方式需要 PyMySQL 再装 `cryptography` 才能登录。所以给项目单独建了一个能用
> `mysql_native_password` 登录的账号 `web`，不动 root，只给它 `web` 库的权限。

### 第 3 步：把模板的 sqlSelect 升级成安全的查询函数

模板的写法：

```python
def sqlSelect(sql):
    conn = pymysql.connect(host='localhost', ..., db='web')
    cur = conn.cursor()
    cur.execute(sql)         # 直接执行拼好的 SQL
    sqlData = cur.fetchall()
    cur.close(); conn.close()
    return sqlData
```

这个写法能跑，但有两个升级点：

1. **返回字典而不是元组**：查询结果用 `DictCursor`，页面里就能写 `row["name"]`，不用记第几列；
2. **参数化查询**：不要把用户输入拼进 SQL（`"WHERE name LIKE '%" + keyword + "%'"` 会被 SQL 注入），
   要写成 `WHERE name LIKE %s`，把关键词作为参数传进去。

项目里的三个函数（`app.py:73` 起）：

```python
def get_connection():
    return pymysql.connect(cursorclass=DictCursor, autocommit=True, **DB_CONFIG)

def fetch_all(sql, params=None):
    conn = get_connection()
    try:
        with conn.cursor() as cursor:
            cursor.execute(sql, params or ())
            return cursor.fetchall()
    finally:
        conn.close()

def fetch_one(sql, params=None):
    rows = fetch_all(sql, params)
    return rows[0] if rows else None
```

然后有机物查询函数 `search_organic()`（`app.py:112`）的逻辑是：

```python
# 1. 关键词和字段做校验（字段必须白名单，不能用户传什么就拼什么）
if field not in FIELD_COLUMNS and field != "all":
    field = "all"

# 2. 拼 WHERE 子句，但只有占位符，没有用户输入
if field == "all":
    where_sql = " WHERE name LIKE %s OR formula LIKE %s OR cas LIKE %s"
    params = [like_value, like_value, like_value]
else:
    where_sql = " WHERE " + FIELD_COLUMNS[field] + " LIKE %s"
    params = [like_value]

# 3. 先 COUNT(*) 得到“共找到几条”，再查前 30 条
total_row = fetch_one("SELECT COUNT(*) AS total FROM organic" + where_sql, params)
rows = fetch_all("SELECT ... FROM organic" + where_sql + " ORDER BY id LIMIT 30", params)
```

> 这是前后端 + 数据库实验最核心的一段：
> **用户输入永远只作为 `%s` 的参数，不拼进 SQL 字符串。**

### 第 5 步：写 templates 里的模板（模板的 render.xxx 就是找这个文件）

模板命名规则：`render.organic(...)` → `templates/organic.html`。

模板第一行必须声明“我接收哪些变量”，要和后端 `render.xxx(...)` 的写法对上：

```html
$def with (rows, total_matches, keyword, field, total_records, db_ok, db_message, field_options)
```

页面里怎么用这些变量：

```html
<!-- 直接把变量输出（Web.py 会自动做 HTML 转义，防 XSS） -->
关键词：“<span>$keyword</span>”，共找到 <strong>$total_matches</strong> 条记录

<!-- 条件 -->
$if db_ok:
    ...
$else:
    <div class="alert alert-warning">$db_message</div>

<!-- 循环：结果表格 -->
$for row in rows:
    <tr>
        <td>$row["id"]</td>
        <td>$row["name"]</td>
        <td>$row["formula"]</td>
        ...
    </tr>
```

表单怎么写（这是前后端连接的入口）：

```html
<form method="get" action="/organic.html">
    <input name="q" value="$keyword">
    <select name="field">
        $for value, label in field_options:
            $if value == field:
                <option value="$value" selected>$label</option>
            $else:
                <option value="$value">$label</option>
    </select>
    <button type="submit">查询</button>
</form>
```

- 表单的 `name="q"` / `name="field"`，就是后端 `web.input(q=..., field=...)` 拿到的名字；
- 提交后浏览器访问 `/organic.html?q=甲醛&field=all`，Web.py 匹配到 `OrganicPage.GET`，
  查完数据库再渲染同一个模板 —— 这就是“前后端连接”的完整一圈。

日历页同理：后端用 `calendar` 模块算好 `weeks`（每行 7 个数字，0 表示空格），
模板只负责 `$for week in weeks: $for day in week: ...` 输出表格，不在 JS 里算。

## 4. 老师/答辩可能会问的问题（速记）

1. **Web.py 怎么把网址和代码对应起来？**
   `urls` 元组写“路径 → 类名”，`web.application(urls, globals())` 生成应用；
   访问 `/organic.html` 就调用 `OrganicPage.GET()`。
2. **GET 和 POST 区别？**
   GET 参数在 URL 上（可刷新、可收藏），本项目的查询表单用 GET；
   POST 参数在请求体里，适合提交表单数据（模板里登录就用 POST 示例）。
3. **后端怎么拿到前端输入？**
   `web.input(q="默认值", field="all")`，名字对应表单控件的 `name` 属性。
4. **模板怎么拿到后端的数据？**
   后端 `render.organic(rows=rows, ...)` 传关键字参数，模板第一行 `$def with (...)` 接收。
5. **数据库怎么查？**
   `pymysql.connect()` 建立连接 → `cursor.execute(sql, params)` → `fetchall()` → `close()`；
   本项目封装成 `fetch_all()` / `fetch_one()`，查询结果用 `DictCursor` 返回字典。
6. **为什么不用 f-string 拼 SQL？**
   用户输入会变成 SQL 语句的一部分，`' OR 1=1 --` 这样就能绕过条件，属于 SQL 注入；
   参数化查询（`%s`）把输入当“值”，不会被当成 SQL 语法。
7. **“前后端连接”体现在哪里？**
   浏览器表单提交 → Web.py 的 `web.input()` 收到参数 → 后端查 MySQL →
   数据交给模板渲染成 HTML → 浏览器显示结果。查询结果里的 271 条、4 条等都是数据库里的真实数据。
8. **有机物查询为什么甲醛是 4 条？**
   数据库表里名称包含“甲醛”的记录正好 4 条（序号 2、53、81、269）。
9. **数据库没启动会怎样？**
   `try/except` 捕获异常，页面显示 `alert-warning` 提示，不会直接 500 崩溃。
10. **静态文件为什么用 `/static/`？**
    `web.httpserver.StaticMiddleware` 把 `/static/` 映射到项目下的 `static/` 目录，
    CSS/JS 由它直接返回，不经过页面处理类。

## 3. 代码里怎么连：三步

**① 建立连接**（`app.py:73`）：

```python
def get_connection():
    return pymysql.connect(cursorclass=DictCursor, autocommit=True, **DB_CONFIG)
```

- `**DB_CONFIG`：把字典里的参数展开成 `host=...`、`user=...` 等关键字参数；
- `cursorclass=DictCursor`：查询结果返回字典，页面里能写 `row["name"]`；
- `autocommit=True`：查询不需要手动 `commit()`；`init_db.py` 是写数据，所以单独用 `autocommit=False` + `commit()`。

**② 执行 SQL、取结果**（`app.py:78`）：

```python
def fetch_all(sql, params=None):
    conn = get_connection()
    try:
        with conn.cursor() as cursor:
            cursor.execute(sql, params or ())
            return cursor.fetchall()
    finally:
        conn.close()      # 用完一定关闭，避免连接泄漏
```

**③ 页面里调用**：

```python
rows = fetch_all("SELECT id, name FROM organic WHERE name LIKE %s", ("%甲醛%",))
```

`init_db.py` 里也是同样的连接方式，只是它负责写数据：
`pymysql.connect(autocommit=False, **DB_CONFIG)` → `execute/executemany` → `commit()` → `close()`。

## 5. 想改连接信息，只改一处

只需要改 `config.py` 里的 `DB_CONFIG`。例如换成本机 root 账号（如果老师要求）：

```python
DB_CONFIG = {
    "host": "127.0.0.1", "port": 3306,
    "user": "root", "password": "你的root密码",
    "database": "web", "charset": "utf8mb4",
}
```

> 注意：MySQL 8.0 默认使用 `caching_sha2_password` 认证，PyMySQL 直接连会报
> “cryptography is required for sha256_password or caching_sha2_password”。
> 解决办法二选一：
> 1. `pip install cryptography`（同时给 Python 装这个依赖）；
> 2. 像本项目一样，建一个用 `mysql_native_password` 认证的专用账号 `web`
>    （见 `sql/setup.sql`），root 账号不用动。

## 6. 模板里的连接 vs 本项目的连接

| | 模板 `index.py` | 本项目 |
| --- | --- | --- |
| 连接位置 | 写在 `sqlSelect`/`sqlWrite` 里，两处重复 | 抽到 `config.py`，统一用 `**DB_CONFIG` |
| 连接时机 | 每次调用新建连接 | 每个请求新建连接，`finally` 关闭 |
| 结果类型 | 元组（按列号取） | 字典（`row["name"]` 按列名取） |
| SQL 写法 | `cur.execute(sql)`，SQL 字符串直接拼 | `cur.execute(sql, params)`，`%s` 参数化 |
| 写操作 | 单独 `sqlWrite` + `commit` | `init_db.py` 中 `commit`，查询页面只读 |

## 7. 常见连接报错对照表

| 报错 | 原因 | 解决办法 |
| --- | --- | --- |
| `1045 Access denied for user 'web'@'localhost'` | 账号/密码不对，或账号没建 | 重跑 `sql/setup.sql`，核对 `config.py` |
| `1049 Unknown database 'web'` | 数据库 `web` 还没建 | 以 root 执行 `sql/setup.sql` |
| `2003 Can't connect to MySQL server on '127.0.0.1'` / `10061` | MySQL80 服务没启动，或端口不是 3306 | `services.msc` 启动 MySQL80，或 `net start MySQL80` |
| `Authentication plugin 'caching_sha2_password' cannot be loaded` / 提示 cryptography | PyMySQL 缺少认证依赖，或账号认证方式不对 | `pip install cryptography`，或使用 `mysql_native_password` 的账号 |
| `ModuleNotFoundError: No module named 'pymysql'` / `'web'` | Python 环境没装依赖，`.deps` 也没带上 | `pip install web.py pymysql`，或复制项目自带的 `.deps` |
| 中文显示成 `???` / 乱码 | 连接、库、表字符集不一致 | 全部统一 `utf8mb4`，CSV 用 `utf-8-sig` 读取 |

## 8. 一句话记住数据库连接

> **连接 = 4 个参数（host/port/user/password）+ database，`pymysql.connect()` 连上，
> `cursor.execute(sql, params)` 执行，`fetchall()` 取结果，最后 `close()` 关闭。**
> 本项目把这几步封装在 `config.py` 和 `app.py` 的 `get_connection/fetch_all/fetch_one` 三个函数里，
> 页面代码只需要“拿参数 → 调函数 → 渲染模板”，不用每次重复写连接。
